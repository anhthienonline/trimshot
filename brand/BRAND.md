# Trimshot — brand guide

A precision capture tool for macOS. Everything here follows from one idea: **the app
measures what is on screen, so its identity is built from the language of measurement** —
crop marks, dimension lines, pixel grids, hex values.

---

## The mark

Four crop brackets around a crosshair. It is the app's own selection UI, reduced to the
simplest shape that still reads at 16 px.

- `brand/mark.svg` — uses `currentColor`, so set `color` on the parent to recolour it
- `Resources/AppIcon.icns` — the macOS app icon, generated by `scripts/make-icon.swift`

**Construction.** In a 100-unit box: brackets at 22 and 78, arms 18 long, stroke 4,
crosshair arms ±8.5 at stroke 1.7. Keep those ratios when rescaling. The gaps between
brackets are load-bearing — close them and the mark stops reading as a crop frame and
becomes a solid ring.

**Optical sizing.** Below 32 px the mark switches to a chunkier variant: bigger frame,
shorter arms, relatively heavier stroke. This is not laziness, it is the same thing type
designers do — at the full weight the gaps disappear at small sizes.

**Clear space.** Keep at least one bracket-arm length (18 units) clear on all sides.

**Don't:** rotate it, add a drop shadow, put the crosshair on a different colour from the
brackets, or fill the interior. The empty middle is the selection.

### Lockup

There is no lockup SVG on purpose. An SVG with live `<text>` silently falls back to a
different typeface wherever the font is missing, which is worse than no file. Build the
lockup from `mark.svg` plus real text: mark at cap height, gap of one bracket arm,
"Trimshot" in the body face at 600 weight with `-0.01em` tracking.

## Colour

The palette is petrol and cool near-white, with a single magenta reserved for one job.

| Token | Light | Dark | Use |
|---|---|---|---|
| `paper` | `#F6F7F8` | `#0C1215` | Page ground |
| `surface` | `#FFFFFF` | `#121A1E` | Cards, panels |
| `ink` | `#10161A` | `#E7EEF0` | Body text, headings |
| `muted` | `#56646C` | `#8A9AA1` | Captions, secondary text |
| `hairline` | `#DDE3E6` | `#212D33` | Rules, borders, ticks |
| `petrol` | `#0E6B78` | `#5FD3DE` | Links, accents, the mark |
| `measure` | `#D81B60` | `#FF6C99` | **Dimension annotations only** |

**Petrol** is the brand colour. On the app icon it appears as a tinted dark tile
(`#163D45` → `#07181C`) with the mark in `#5FD3DE` — a plain near-black tile reads as
unconsidered, and the light mark is what survives 16 px against an arbitrary wallpaper.

**Measure magenta has exactly one job:** dimension lines and their numbers. Design tools
colour measurement overlays this way, so it carries meaning rather than decoration. Using it
for a button or a heading spends the one signal the palette has.

The neutrals are biased cool, toward petrol. A pure grey would read as inherited.

**Not the Gravity Global green.** The app started with `#b7e39b`, which is an employer's
brand colour. On a portfolio piece that misattributes the work.

## Type

| Role | Stack | Why |
|---|---|---|
| Display & body | `-apple-system, "SF Pro Display", "SF Pro Text", system-ui` | This is a macOS-native app; setting it in the platform's own typeface is the honest choice, and it needs no webfont |
| Data & UI | `ui-monospace, "SF Mono", Menlo, monospace` | Dimensions, hex values, keyboard shortcuts, file sizes |

Never link a webfont from a CDN. A strict CSP or an offline viewer turns that into a silent
fallback, and a brand that depends on a network request is not a brand.

**Rules.** Body text near 65 characters wide. Headings get `text-wrap: balance` and
`-0.02em` tracking at display sizes. Uppercase labels get `0.08em` tracking and never run
longer than a few words. Anywhere digits line up in a column, use
`font-variant-numeric: tabular-nums`.

**Always monospace:** dimensions (`1440 × 900 px` — always CSS pixels), hex values (`#181818`),
keyboard shortcuts (`⌃G`), sizes (`520 KB`). These are data, and data is set in the data
face.

## The dimension-line device

The one structural flourish. A hairline with end ticks and a monospace number in the middle,
in measure magenta — a real annotation from a spec drawing.

Use it to mark something the reader would otherwise have to guess at: the size of the mark,
the dimensions of a screenshot, the width of a layout. **Do not use it as a divider.** It
means "this has been measured". If it appears where nothing was measured, it is a lie and
the device stops working everywhere else.

At most two per screenful.

## Voice

Plain, specific, measured. The app's whole promise is that the numbers are exact, so the
writing has to earn the same trust.

- **Say the number.** "Matches macOS's own capture to 0.01/255" beats "pixel-perfect".
- **Name things the way the reader does.** "Copy the colour under the cursor", not
  "sample the pixel buffer".
- **No superlatives.** No "blazing fast", "seamless", "powerful", "effortless".
- **State limits.** "Captures stay on your machine — there is no upload" is a feature and a
  boundary at once. Saying what a tool does not do builds more trust than another adjective.
- **Errors say what happened and what to do.** "Trimshot needs Screen Recording
  access" then the exact path through System Settings. No apologies.

Sentence case for headings and buttons. A button names the action; the confirmation uses the
past tense of that same verb — *Save* then *Saved*.

## Applying it

**App icon.** `swift scripts/make-icon.swift --preview`. Full-bleed artwork: macOS 26 wraps
every legacy `.icns` in its own squircle plate, so drawing another rounded shape nests a
dark tile inside a light one. Use `--framed` for macOS 14 and 15, which apply no mask.

**Screenshots for a README or a post.** Capture on the cool paper ground, not on a desktop
wallpaper. Let the app's own dimension label do the annotating.

**Anything with a colour in it** should pull from the table above rather than eyeballing a
near-match. If a value is not in the table, it is not in the brand.

## The name

**Trim** is the prepress term for cutting a sheet down to its exact finished size — the trim
marks sit right beside the crop marks on any proof. That is precisely what a crop is, so the
name comes from the same vocabulary as the mark. **Shot** carries the category, so nobody has
to guess what the app is.

It replaced "Screenshot Custom", which named a category rather than a product: unsayable,
unsearchable, and nothing for an identity to hold on to.

**Say it as one word, capital T only** — Trimshot, never "TrimShot" or "Trim Shot".

Candidates that were checked and rejected, in case the question comes up again:

| Name | Why not |
|---|---|
| Caliper | "Screen Calipers" already ships in this exact category |
| Reticle | Searches land in FPS crosshair-overlay territory |
| Pica | Taken twice on the Mac, including a font manager |
| ShotMark | Taken — and it is a screenshot app with OCR |
| TrueShot | Taken twice |
| Trimbox | Taken by an email cleaner |

That checking was ordinary web searching, **not** a trademark or App Store registry search.
Before putting the name on anything public, verify it properly.

### The cost of renaming again

The bundle identifier is baked into the app's designated requirement, so changing it **resets
the Screen Recording permission and the login item on every machine that has it installed**,
and every user grants access again. Cheap now, expensive later.

The identifier is `com.thienho.trimshot`. Reverse-DNS identifiers are meant to be built from
a domain you control — point that at a domain you own before publishing.
